    One-line verdict

    The CatBoost champion (test ROC‑AUC 0.934) is a reasonable model on this synthetic problem — but the interesting finding is methodological: the Step 8.5 full-data refit shifted scores enough that the pre-refit calibration had to be discarded, exactly the scenario the “check, don’t assume” rule was written for.

    Operating table — champion, swept by FPR 0–5% in 0.25% steps

    Expected cost vs. operating FPR
    $50 per false positive · $2,000 per false negative · minimum marked

    Cost is high at low FPR because a low FPR forces a high threshold, and a high threshold misses defaults: at FPR=0% the champion's TPR is only 38.8%, so 61.2% of actual defaulters in the test window are false negatives — and at $2,000 per missed default vs. $50 per unneeded review (40×), even a modest miss rate outweighs the near-zero false-positive cost. Cost falls as the threshold drops and TPR climbs, until FP volume catches up around FPR≈4.5%, which is where the minimum sits.

    FPR%ThresholdTPRPrecisionRecallF1
    Recommended operating point

    FPR ≈ 4.5%, threshold ≈ 0.405 — minimizes expected cost ($58,355 across the 1,200-record test window, see chart above) against the business constraint from Section 1. $181,632 cheaper than reviewing nothing.

    Model Interpretability

    done

    Champion: CatBoost. TreeSHAP throughout — global via mean |SHAP|, local via three fixed cohorts.

    7.1 Global explanations

    Variable importance
    mean |SHAP value|, test window, top 10
    ICE + PDP — top 3 variables
    faded lines = 40 individual test records · bold line = PDP, the population average

    PDP alone can hide effects that cancel out across records — e.g. the variable raising risk for some records while lowering it for others. Showing the individual ICE curves underneath is how you'd catch that; here they run mostly parallel to the PDP line, so no such heterogeneity shows up.

    ALE — top 3 variables
    accumulated local effect on P(default), centered at zero · 12 quantile bins

    PDP can extrapolate into unrealistic feature combinations when inputs are correlated (e.g. sweeping credit_utilization while holding debt_to_income fixed, even for records where the two never co-occur that way). ALE only ever averages over the local neighborhood a value actually appears in, so it's the more defensible read when features are correlated — compare its shape against the PDP panel above for the same three variables.

    feat_misc_1 ranking highly is a quirk of the synthetic generator, not a real signal — every top-ranked variable needs a business-meaning sanity check before being trusted.

    Final Fit for Deployment

    done

    CatBoost refit on the full dataset (n=6,000 = train+eval+test), same hyperparameters, no re-tuning.

    Calibration-drift check
    pre-refit vs. post-refit score, same test-window records (300 sampled)
    Decision: recalibrate

    Mean |post − pre| score diff = 0.058, correlation = 0.908 — a meaningful shift, not noise. The pre-refit calibration curve and score bands do not carry forward unchanged onto the final deployment model. (Flag: recalibrating on these same test-window records is slightly optimistic, since they also trained the refit model — a real project should hold back one more small recent slice before the full refit for a clean check.)

    This is the clearest finding of this simulated run — “maybe not” was the wrong instinct here.
